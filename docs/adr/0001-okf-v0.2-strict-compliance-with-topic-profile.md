# OKF v0.2 严格合规 + Topic Profile

Status: accepted

Bundle 格式严格遵循 GoogleCloudPlatform/open-knowledge-format v0.2 规范：每个 Topic 是一个 markdown + YAML frontmatter 的 concept 文档，唯一必选键 `type: Topic`；本插件在其上定义 Topic Profile（扩展键 `depends`/`open_questions`/`impact` + 约定正文标题 `# Conclusion`/`# Recommendations`），并原样启用 OKF 的 provenance（`sources`）、trust（`generated`/`verified`）、lifecycle（`status`/`stale_after`）三族可选字段。

## Considered Options

- 自定极简 schema（否决）：出了 dsh 生态就不可读，且失去 Obsidian/OKF 校验器/viz 等现成消费端。
- 借鉴 Karpathy llm-wiki 方法论自建（否决）：方法论无正式格式规范，跨工具迁移需重写。

## Consequences

- 自动观察写入的每个 Topic 必须带 `generated: {by, at}` 标明是机器产物，人工修订走 `verified`，信任分层由此免费获得。
- 结论「git 可追溯」与 OKF 的 trust/lifecycle 字段互补：git 管「结论怎么变的」，frontmatter 管「当前该信多少、是否过期」。
- 未来若换宿主（pi、Claude Code 等），Bundle 无需迁移。
